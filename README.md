# X Keyword Blocker

当前版本：**1.4.0**

一个轻量、无依赖的 Tampermonkey / Violentmonkey 用户脚本，通过关键词自动隐藏 X（Twitter）时间线中的帖子。支持 `x.com` 和 `twitter.com`。

## 主要功能

- 不区分大小写的关键词子串匹配
- 自动规范化全角、半角等 Unicode 字符
- 可选匹配作者显示名称和用户 ID（`@username`）
- 独立识别并屏蔽 X 的“广告 / Promoted / Sponsored”等推广帖子
- 只检查新增或发生变化的帖子，减少长时间滚动时的性能开销
- 一键暂停或恢复全部过滤
- 持久保存累计拦截次数
- 批量拦截时显示累计总数和 `+N` 浮动动画
- 从本地 TXT 文件或 HTTPS 文本网址导入关键词
- 将当前关键词导出为 UTF-8 TXT 文件
- 自动适配 X 的浅色、Dim 和深色外观
- 支持键盘操作、焦点管理和移动端布局

## 安装

1. 安装 Tampermonkey、Violentmonkey 或其他兼容的用户脚本管理器。
2. 新建用户脚本，将 [`x-keyword-blocker.js`](x-keyword-blocker.js) 的内容完整粘贴进去。
3. 保存脚本，然后打开或刷新 `x.com` / `twitter.com`。

升级脚本时会保留已有关键词、累计拦截数和开关设置。

## 打开管理面板

推荐从用户脚本管理器菜单中选择“管理屏蔽关键词”。也可以使用以下快捷键：

- Windows / Linux：`Alt + Shift + K`
- macOS：`Option + Shift + K`

部分浏览器或输入法可能占用快捷键；这种情况下请使用用户脚本菜单。

## 设置

| 设置 | 默认值 | 作用 |
| --- | --- | --- |
| 过滤状态 | 开启 | 总开关，控制关键词、作者信息和广告过滤是否运行 |
| 浮动拦截提示 | 开启 | 批量拦截后显示累计总数和 `+N`，1 秒后消失 |
| 匹配作者名称与 ID | 关闭 | 同时匹配帖子正文、作者显示名称和 `@username` |
| 屏蔽广告 | 开启 | 独立隐藏带“广告 / Promoted / Sponsored”等推广标记的帖子 |

开启“匹配作者名称与 ID”后：

- 关键词 `处男无偿` 可以匹配显示名称 `曼曼处男无偿`。
- 关键词 `qdcbtwnfxmtzjx` 或 `@qdcbtwnfxmtzjx` 都可以匹配账号 ID `@qdcbtwnfxmtzjx`。

显示名称匹配仅在该开关开启时生效。

“屏蔽广告”与关键词列表相互独立：即使列表中没有“广告”或“推广”，甚至清空了全部屏蔽词，只要该开关保持开启，推广帖子仍会被隐藏。关闭此开关后，推广标记本身不会触发屏蔽，但帖子正文或作者信息仍可能命中普通关键词。

管理面板会把“匹配作者名称与 ID”和“屏蔽广告”两个开关并排显示，方便快速调整。

## 导入与导出

TXT 文件采用“一行一个关键词”的格式：

```text
广告
推广
crypto
airdrop
抽奖
```

导入前会显示有效项、重复项、空行和无效项的统计，并提供两种方式：

- **合并导入**：保留当前列表，只添加尚不存在的关键词。
- **替换现有**：用导入内容覆盖当前关键词列表。

限制：

- 最多保存 2,000 个关键词
- 每个关键词最多 100 个字符
- 导入文件最大 512 KB
- 网址导入仅接受 HTTPS 地址
- 网址服务器必须允许浏览器跨域读取；GitHub Raw 等公开文本地址通常可用

屏蔽词数量右侧的“清空”按钮可以一次删除全部关键词。执行前会显示确认提示；确认后无法撤销，但不会改变广告屏蔽、作者 ID 匹配等开关设置。

## 累计拦截计数

“累计拦截”是保存在当前浏览器中的长期累计值，不会在刷新或重新打开浏览器时自动清零。

同一个帖子在一次页面会话中只计数一次，避免 X 动态重复渲染导致虚增；刷新后会开始新的页面会话，同一帖子再次被脚本隐藏时会再次计数。

示例：

```text
当前累计：100
页面屏蔽 10 条：110
刷新后再次屏蔽同样的 10 条：120
再次刷新：130
```

点击面板中的“清零”只会重置累计数，不会删除关键词或更改其他设置。

## 隐私

- 关键词、设置和累计数保存在用户脚本管理器的本地存储中。
- 脚本不会上传关键词、浏览记录或帖子内容。
- 只有主动使用“从网址导入”时，浏览器才会请求所填写的 HTTPS 地址。

## 故障排查

如果某个帖子没有被屏蔽，请检查：

1. 主过滤开关是否开启。
2. 关键词是否已成功加入列表。
3. 如果关键词位于显示名称或 `@username` 中，“匹配作者名称与 ID”是否开启。
4. 更新脚本后是否刷新了 X 页面。

X 的页面结构可能随时调整。如果 X 修改了 `data-testid="tweet"`、`data-testid="tweetText"` 或 `data-testid="User-Name"`，相关选择器可能需要同步更新。
